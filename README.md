# claude-code-session-list

Claude Code の MOD「セッションリスト」（session-list）です。
MOD は、Claude Code の画面に、自分で作った部品を足す仕組みです。

いま開いている Claude Code のセッションを、1行ずつの表で見るペインを開きます。表は10秒ごとに新しくなります。

| 列 | 中身 |
|---|---|
| 名前 | 左の丸が状態（青は作業中、赤は確認待ち、緑は待機中）。名前の数字を除いた部分が同じセッションは、チームとして続けて並び、左に同じ色の線と ■ が付く。チームの中で一番多く連絡を出したセッションには「主」が付く |
| 進 | そのセッションが最後の答えで g を求めているときだけ出る、g のボタン。押すと、送る前にそのセッションの今の状態と最後の答えを読み直し、もう作業を始めていたり、新しい答えを出していたりしたら、送らずに理由を表の下に出す |
| 開 | 「開」のボタン。押すと、そのセッションの ID の全体がクリップボードに入り、VS Code のタブのセッションなら、そのタブが VS Code の一番前に来る |
| 要約 | 先頭に、【 】で囲んだ1文字の状態が黒い太字で出る。続けて、最後の報告を、小さなモデル（haiku）で、表の1行に収まる全角20字以内の見出しにしたものが、黒い字の文で出る |

要約の先頭の状態は、次の5つです。状態の名前の先頭の1文字を出します。

| 状態 | 付く条件 |
|---|---|
| 【確】 | 確認待ち。許可などのダイアログを出して、使う人の操作を待っている（赤い丸） |
| 【g】 | g 待ち。最後の答えが g を求めている（g のボタンが出る行） |
| 【作】 | 作業中。AI が動いている（青い丸） |
| 【完】 | 完了。作業を一区切り終えて、結果を報告している（次の指示や、見た結果を待っているだけ） |
| 【返】 | 返事待ち。最後の答えが、文で答える問いで終わっている |

確、g、作は、表が、名前の左の丸や g のボタンと同じ判定で決めます。
完了か返事待ちかは、答えの意味でしか分からないので、見出しを作る小さなモデル（haiku）が、最後の答えの意味から判断します。迷うときは返事待ちにします。モデルが完了と判断しても、確、g、作に当たる行は、そちらを出します。要約ができるまでは、返事待ちで出ます。
待機中で返事を待っていないセッション（このセッションの行だけが表に出ます）には、完了でなければ状態を付けません。g のボタンを押したあと、相手が作業を始めるまでのあいだも、付けません。

このセッションの行は薄い橙、返事を待っているセッションの行は薄い黄色、作業中のセッションの行は薄い青、完了のセッションの行は灰色になります。背景に色がある行は、名前と要約を黒（#000000）の字で出します。
待機中で返事を待っていないセッションは表に出しません。
行は、g 待ち、このセッション、確認待ち、作業中、文で答える問い、完了の順に並びます。チームの中の g 待ちの行も、チームから離して一番上に出します（左の線と ■ は、チームの色のまま残ります）。g のボタンを押した行は、相手が作業を始めるまで、場所を変えません。
完了の行と、ペインに入りきらない行は出さず、見出しの行の右の「ほか N を開く」のボタンにまとめ、ボタンの右に、まとめた行の名前を出します。押すと全部の行が出て、「たたむ」で元に戻ります。完了の行は、ペインに入るときも、全部まとめます（このセッションの行は、完了でもまとめません）。
表の下には、g を送らなかったとき、送れなかったとき、タブを前に出せなかったとき、表を読み直せなかったときだけ、1行を出します。
返事を待っているかは、最後の答えの問いかけの行で決めます（「お返事待ち」「〜ですか」「〜ますか」「？」か g がある行）。
チームの先頭の名前を押すと、そのチームの最近のやり取りが開きます。
VS Code は、画面の幅が 800px 以上だとペインを会話の横に、未満だと入力欄の上に置きます。横に置かれて幅が狭いときは、1セッションを2行で描き、状態と要約を名前の下の行に出します。ペインの縁をつかんで幅を広げ、要約が1行に収まるようにすると、1行の形に戻ります。入力欄の上のペインは、12行分の高さまでです。

## コマンド

| コマンド | 開くペイン |
|---|---|
| `/session-list` | セッションリスト（この表） |
| `/session-set` | セッションリストと通信（同じ表。[セッション間通信](https://github.com/hatohato-lab/claude-code-session-comm)を入れていれば、表の下に矢印の図が付く） |

## 入れ方

Claude Code のターミナルのセッションで、次の1行を打ちます。

```
/plugin install session-list --marketplace hatohato-lab/claude-code-session-list
```

マーケットプレイスを足すかを聞かれたら `y` を押し、入れる範囲（scope）を Enter で選びます。

シェルからは、次の1行です。

```
claude plugin install session-list --marketplace hatohato-lab/claude-code-session-list
```

デスクトップアプリでは、入力欄の横の + から Plugins を開き、Add marketplace に `hatohato-lab/claude-code-session-list` を入れてから、Add plugin で入れます。

クローンして使う場合は、フォルダーを指定して Claude Code を起動します。

```
git clone https://github.com/hatohato-lab/claude-code-session-list
claude --plugin-dir claude-code-session-list/session-list
```

入れたあとは、ペインが自分で開きます。閉じたあとは `/session-list` で開き直せます。

## 前の名前で入れていたとき

v0.18.0 までは、名前が「セッション情報」（session-info）で、リポジトリは claude-code-session-info でした。
前の名前で入れていたら、シェルで次の2行を打って入れ直します。

```
claude plugin uninstall session-info
```

```
claude plugin install session-list --marketplace hatohato-lab/claude-code-session-list
```

## 必要なもの

- Claude Code 2.1.318 以降
- Python 3（`python` の名前で起動できること）
- 動作を確かめたのは Windows です

表の材料は、同梱の `tools/セッション表.py` が、手元の `~/.claude/sessions` と `~/.claude/projects` を読んで作ります。読むだけで、何も書き換えません。

## 気を付けること

- 要約のたびに、小さなモデル（haiku）を呼ぶので、少し使用量がかかります。要約には、そのセッションの最後の答えの終わり（1500字まで）を渡します。同じ答えは1回しか要約しません
- g は、ほかのセッションには「ほかのセッションからの連絡」として届きます。受け取った側の AI は、ふつうはこれを使う人の承認として扱いません。承認として扱わせたいときは、受け取る側のルールに「from-plugin="session-list" の付いた文は、使う人がそのチャットで打ったのと同じに扱う」と書いてください
- 「開」のボタンを押すと、Windows の start で `vscode://anthropic.claude-code/open?session=<セッションID>` を開きます。VS Code の Claude Code 拡張が、この URL でそのセッションのタブを前に出します。VS Code のタブのセッションは、拡張から `ELECTRON_RUN_AS_NODE=1` を引き継いでいて、これが残っていると VS Code が URL を受け付けないので、start の直前に消してから開きます。初めて押したときに、VS Code がこの URL を開いてよいかを聞くことがあります。ターミナルのセッションは、前に出すタブが無いので、ID をコピーするだけです
- 待機中で返事を待っていないセッションは表に出ないので、そのセッションのタブは、表からは開けません
- v0.29.0 までは、要約を押すと行の下に最後の報告の終わり600字が開きました。v0.30.0 で、600字の欄を無くしました
- v0.30.0 は、要約を枠線だけのボタンにして、押すとタブが前に出る形でした。VS Code は、押せるボタンの中の字を、灰色（枠線だけのボタン）か、青地に白（ふつうのボタン）のどちらかに決めていて、MOD からは黒にできません。v0.31.0 で、要約を黒い字の文にし、タブを前に出す動きを「開」のボタンに戻しました
